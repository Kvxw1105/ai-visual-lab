# Video Source Acquisition

把用户给的公开分享链接转换成**可验证的本地分析输入**。先分清需要的是单条视频、字幕/文案，还是作者维度的批量语料；不要把“解析接口返回成功”当成文件已经下载。

## 1. 先选获取目标

- **单条视频，做画面/动效/镜头分析**：获取视频文件，记录下载件的分辨率、帧率、时长、编码与 SHA-256。
- **字幕/文案为主**：优先检查平台是否提供可合法访问的字幕/文本导出；没有时，对用户提供或已获准取得的单条视频本地做 ASR/OCR。视频下载站不保证提供字幕。
- **作者主页、多个作品、限定时间范围**：先给出范围（平台、作者、日期区间、目标字段），再找平台官方导出/API 或逐条公开分享链接。本文列出的站点只验证过**单条分享链接**，不宣称支持主页全量抓取；不得用多站轮换来规避频次限制。

### 自动化时观察到的前端适配（易变，调用前重验）

如隔离浏览器不可用，可在无 Cookie 的情况下复用这些**当前页面自身**的解析请求；先重新检查页面脚本/表单，不能把它们当作稳定 API：

- PeanutDL 抖音：`POST https://xapi.peanutdl.com/douyin`，JSON 至少包含 `{ "api": "DOUYIN", "url": "<分享链接>" }`。前端还带有验证码字段；字段为空仅表示当前请求未提交挑战，若服务实际要求 CAPTCHA/Turnstile 就停止，不伪造或绕过。
- PeanutDL 哔哩哔哩：`POST https://xapi.peanutdl.com/beibei`，JSON 至少包含 `{ "api": "BEIBEI", "url": "<分享链接>" }`；已观察到成功响应为 `status == 0`，MP4 链接位于 `mp4.player_url`。
- v.mtotech：`POST https://v.mtotech.com/api/resolve`，JSON `{ "url": "<视频号分享链接>" }`；成功响应中的 H.264 地址位于 `data.h264_url`。

这些字段来自站点前端当前实现，不是服务商承诺的长期接口。仅把返回链接保存在进程内并立即下载；不输出到终端、不写日志或仓库。遇到 schema 变化、验证码、登录要求、拒绝或限流，停止并回到站点公开页面说明状态，不尝试绕开。

## 3. 执行与验证

1. 校验链接属于用户指定的平台，保留原始分享链接作为来源；只读取公开内容。
2. 解析成功后立刻下载。文件放在当前分析项目的 `output/` 或工作区 `outputs/`，不要把视频、Cookie、临时直链提交进公开仓库。
3. 检查下载件存在且非空；用 `ffprobe` 读取容器、视频/音频编码、时长、分辨率和帧率；用 `ffmpeg` 完整解码到空输出，确认退出码为 0 且无解码错误；计算 SHA-256。
4. 报告中区分“原作品”与“下载件”：分辨率/码率/文件大小属于本地下载副本，不代表源作品最高规格。记录来源平台、解析站、获取时间、文件路径、下载件元数据、哈希、验证结果及失败/限制。
5. 若只有解析结果、没有本地文件，写“解析完成，下载未完成”；若没有完整解码，只能写“文件已下载，解码未验证”。

## 4. 停止条件与隐私边界

- 需要登录、验证码、人机验证、付费、DRM、私密权限，或返回访问拒绝时停止；不绕过、不伪造凭据、不切换代理/账号来规避限制。
- 服务商提示频率限制时停止并如实报告；备用站只用于服务临时不可用且站点规则允许的情况，不能用于绕过限制。
- 不点赞、关注、评论、转发、私信或发布内容。不要把临时签名 URL、Cookie、账号标识或视频文件写入公开仓库、报告或调试日志。
- 只处理用户有权使用的内容，并遵守平台规则及适用法律；需要处理作者全量作品时先确认范围和权限，再单独设计采集与留存方案。
